# v1.2.0

> 🎬 **录制功能** —— 让用户一键把终端显示的全部内容（RX + TX + 系统消息）抓到本地 .txt 文件，便于离线分析。
> 用户原话："现在显示窗口的数据还无法保存，当我在使用串口连接抓取日志的时候就没办法保存下来分析。"
> 本次 v1.2.0 彻底解决。

## 变更

### ✨ 录制功能（核心）

#### 1. 工具栏"⏺ 录制"按钮 + "⏹ 停止录制"按钮

点"⏺ 录制"：
- 根据 `Settings → 每次录制时弹文件对话框` toggle 决定行为
- **toggle 开**：弹原生文件对话框（`@tauri-apps/plugin-dialog` 的 `save()`），用户选 `.txt` 路径
- **toggle 关**：直接用 `Settings → 默认保存路径` + 自动文件名 `capture-{port}-{YYYYMMDDHHmmss}.txt`

点"⏹ 停止录制"：`flush` + 关闭文件 + `console.info` 输出 summary（KB / 耗时 / 路径）。

按钮颜色：
- 未激活：灰底白字（与其他工具栏按钮一致）
- 激活中：**红底 + animate-pulse 闪烁**（与"关闭串口"红色按钮区分）

#### 2. 状态栏 REC 指示

录制中状态栏左侧 TX/RX 旁出现红色 REC 指示：

```
● REC 1.2 MB       ← 正常
● REC 1.2 MB ⚠    ← > 500MB 橙色警告（Q15A）
```

- 与 TX/RX 一致 `useRafValue` 节流到 15Hz（store 仍 60Hz 累积，精度不丢）
- 文件 > 500MB 时尾部追加橙色 ⚠ 警告 tooltip
- 录制指示位置：TX 之后，溢出之前

#### 3. 录制文件格式（纯文本，去 ANSI）

**文件头**（自动写）：
```
# OhMySerial Capture — COM3 @ 115200 8 1 none — 2026-06-22 14:35:12 (v1.2.0)
```

**RX / TX 数据行**（与终端显示一致，但去 ANSI）：
```
[14:35:12.456] ← [HEX] AA BB CC DD EE FF 11 22
[14:35:12.520] → [HEX] 01 02 03
[14:35:13.001] ← hello world
```

格式规则：
- 每行 Unix LF 换行
- 时间戳：`[HH:MM:SS.mmm]` 本地时间
- 方向箭头：`←` RX（蓝字 ANSI 256 在终端）/ `→` TX（绿字 ANSI 256 在终端）
- HEX 视图加 `[HEX]` 标签（便于 grep）
- TEXT 视图不加标签（按 UTF-8 / GBK 解码）

**断线 / 重连事件**（`# 注释行`，便于离线分析识别数据缺口）：
```
# [2026-06-22 14:35:12.456] 设备已断开: BrokenPipe
# [2026-06-22 14:35:47.123] 重连成功 (gap 34.667s)
```

**系统消息**（如 `port-disconnected`）：
```
# [2026-06-22 14:35:15.789] [系统] 设备已断开: Broken pipe
```

#### 4. 重连不切文件（关键设计）

设备断开 → 自动重连 → 重连成功，**整个过程写到同一个文件**。文件里通过 `# 注释行` 标记断线 / 重连时刻和 gap 时长。

设计原因：工业抓包场景里用户可能遇到：
- CH340 短接松动 → 设备短暂断开 → 自动重连
- 拔下串口看其他设备 → 插回继续

如果断线就切文件，用户得手动拼文件、丢失数据缺口信息。

#### 5. closePort = 录制结束（Q13A）

用户主动关闭串口（点"关闭串口"按钮）→ 自动停止录制 + console.info 提示 summary。

反面选择：不保留跨 session 的"暂停录制"语义（工业抓包都是连续 session）。

### 🔧 关键架构决策（写进 CLAUDE.md 关键设计决策 #27-32）

1. **Recorder 是纯字符串 sink（v1.2.0）**：Rust 端不持 HEX/TEXT/编码知识，只接收前端 `formatLine` 格式化好的字符串行，写盘 `BufWriter` 不做解析。**设计收益**：(a) 加新格式（CSV/JSON）只需改前端 formatLine + 新 IPC type，Rust 不动；(b) Rust 单元测试不需要 mock xterm，纯文件 I/O 可测；(c) 前端 Terminal 和 Recorder 共用同一行格式 → 所见即所录。

2. **重连不切文件（v1.2.0）**：Recorder 是 `Arc<Mutex<Option<>>>` 挂在 SerialState 上，跨 reader 线程生命周期（断线/重连都不释放）；断线/重连事件通过 `mark_event` 写 `# 注释行`（含 `gap X.XXXs`），便于离线分析时识别数据缺口。**与 v0.5.0 schedule_reconnect 复用同 channel 是同款设计**（共享状态透传给新线程）。

3. **closePort = 录制结束（v1.2.0 Q13A）**：用户主动 closePort 时自动 stop 录制 + `console.info` 提示 summary（KB / 耗时）。

4. **formatLine 提取为可测试纯函数（v1.2.0）**：从 Terminal.tsx 提取 `formatTimestamp` / `byteHex` + 新增 `formatLine` 到 `src/utils/terminalFormat.ts`，Terminal.tsx re-export 保持 backward compat（`tests/frontend/terminal.test.ts` 直接 import formatTimestamp 测试）。**便于单测**——jsx 组件在 jsdom 下挂载 xterm 是已知坑（v1.1.0 TerminalFont.test.ts 注释），纯函数零依赖可放心覆盖。

5. **CustomEvent 通信解耦（v1.2.0 SettingsPanel）**：⚙ 按钮在 SerialToolbar 里，触发 SettingsPanel 在 App 根级渲染。两者层级差 3 层，prop drilling 累赘；用 `window.dispatchEvent('oh-my-serial:toggle-settings')` + App.tsx `useEffect addEventListener` 解耦。**未来加更多 Modal（如 About / Help）也可走同一事件名 + 不同 custom event**，无需引入新的状态管理库。

6. **集成测试放单元测试模块（v1.2.0 教训）**：`tests/recorder_integration.rs` 原本想测"同路径 resume / drop flush / 并发写入"，但 `use oh_my_serial::*` 会拉入 Tauri runtime 触发 Windows `STATUS_ENTRYPOINT_NOT_FOUND`（`config_json_shape.rs` 注释已记录）。**改方案**：3 个集成场景直接放 `recorder/mod.rs` 的 `#[cfg(test)] mod tests`，作为单元测试运行——绕开 Windows 入口点问题，测试逻辑不变。

## 不在本版本范围内（v1.3+ 候选）

- 录制文件 **自动按大小滚动**（避免单文件过大）
- 录制 **暂停/继续** 语义（v1.2.0 选择 start/stop 模式）
- 录制文件 **加密 / 压缩**
- 终端 ANSI 颜色也写入（v1.2.0 选纯文本，便于 grep；如需彩色可用 `cat` 或 `less -R`）
- 录制文件格式 CSV / JSON 导出（v1.2.0 选 .txt，最通用；可由第三方脚本转换）
