## 变更

### 🐛 UI 布局修复

#### 1. 字号变大时整页横向滚动条

**症状**：用户截图 18px 字号下底部 StatusBar 出现横向滚动条；24px 下整个应用出现横向滚动条。

**根因**（两层叠加）：

- `App.tsx` 根容器 `<div h-screen>` 没有 `overflow-hidden` —— v1.1.0 撤掉了 commit 52e132b 的防御
- `StatusBar.tsx` 用了 `overflow-x-auto` —— 内容溢出时显示横向滚动条（用户反馈"不希望看到"）

**修复**：

- `App.tsx:165` 根容器加 `overflow-hidden`（恢复 commit 52e132b 的兜底）
- `StatusBar.tsx:68` 改 `overflow-x-auto` → `overflow-hidden`，右侧组加 `truncate`，版本号加 `whitespace-nowrap`
- `SerialToolbar.tsx:168` 字号步进器 `min-w-[5rem]` → `min-w-[80px]`（绝对像素，根除 rem 联动风险）
- `FontPicker.tsx:100` 触发按钮 `min-w-[10rem]` → `min-w-[160px]`（同上）

#### 2. **16px+ 字号下右侧栏被挤出视口**（隐藏最深的 bug）

**症状**：用户截图 16px 字号下，右侧"发送"和"预设命令"面板**整体被推出视口**——只看到"HEX"、"发送"按钮边缘、"预设命令"标题，textarea 被裁，"添加"按钮完全在视口外。**14px 没事，16px 才开始出错。**

**根因**（4 层连锁）：

1. xterm 内部 `.xterm-screen` 的 canvas 元素用 inline `width`/`height` 属性设置 `cols × cellWidth` 实际尺寸
2. **Terminal 根 div** `<div className="h-full w-full" />` 在 flexbox 中默认 `min-width: auto` = 内容最小宽度，**被 xterm canvas 撑大到 > 父容器宽**
3. **Terminal 父容器** `<div className="flex-1 ... overflow-hidden border">` 同样 `min-w: auto`，最小宽度跟着被撑大
4. **CSS 规范**：`min-width: auto` 优先级 > `flex-shrink: 0`，**右侧栏** `<div className="w-80 flex-shrink-0">` **被 flexbox 算法挤压让位给 flex-1 的最小内容宽度**，整体推出视口

**为什么 14px 没事 / 16px 出事**：`cellWidth` 随字号线性增长，16px+ 时某些字体让 xterm-screen 实际宽度 > Terminal 父容器宽。

**修复**（4 处 `min-w-0` + 1 处 `overflow-hidden`）：

- `App.tsx` 中间区外层 flex 容器：加 `min-w-0`
- `App.tsx` 中间区-左 flex 容器：加 `min-w-0`
- `App.tsx` 终端外层 div：加 `min-w-0`（保留原 `overflow-hidden border`）
- `Terminal.tsx:191` 根 div：加 `min-w-0 min-h-0 overflow-hidden` + 详细注释解释原理

> **`overflow-hidden` 不会让终端功能失效**：xterm 内部 `.xterm-viewport` 自带 `overflow: auto`，仍能滚动单行/翻页。`overflow-hidden` 仅裁掉 Terminal 根 div 多余的 canvas/viewport 延伸。

#### 3. 复盘教训（写进 CLAUDE.md 关键设计决策）

> **看到 "UI 布局变了" 的反馈时，先看截图，再追 flexbox 布局。**
> **不要被"字号调节"这个表面症状误导去改字号/字体相关代码。**
> **xterm canvas 撑大 flex 子项是一个 4 层连锁（xterm 内部 → Terminal 根 div → Terminal 父容器 → flex 容器 → 兄弟元素），必须把整条链路上的 `min-w-0` 都补上。**

> **`min-width: auto` 的优先级比 `flex-shrink: 0` 高** —— CSS 规范明文。以为"右侧栏 `flex-shrink-0` 就稳了"是错的，**必须 `min-w-0` 才能真正阻断 flex-1 子项被内容撑大**。
